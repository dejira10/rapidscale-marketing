# Frankie — Frameworks

Frankie's framework is the baseline. Saad's and Aaron's skills may borrow its
structure later, but not its content.

This skill is the single source of truth for how Frankie thinks and works. The
other Frankie skills (`frankie-market-research`, `frankie-outreach`) read from it.

## Reference files

| File | Read it when you need |
|------|------|
| `references/frameworks.md` | The overview, the whole system on one page, core beliefs. **Always read first.** |
| `references/research.md` | Who to sell to, shoe stores and buyers, finding and scoring symptoms, industry language |
| `references/offers.md` | Offer matrix, TIMER, handraisers, specificity, add-on offers, coffee date / first date / marriage, IVQ pricing, proof and risk |
| `references/conversations.md` | Running a sales conversation in text: opening, parroting, Heaven/Hell Island, presenting the plan, closing, objections |
| `references/loom-and-doc.md` | Building the 5-minute Loom or Google Doc, onboarding, pre-sell content |
| `references/outreach.md` | Cold messages, cold email, follow-up sequences, influencer and shoe-store outreach, direct mail |
| `references/voice.md` | How Frankie sounds, and what to leave out |
| `references/source-index.md` | Where every `[Zn]` tag comes from, and what's still unread |

## Hard rule: source-only

- Everything in the reference files traces to a source in `source-index.md`. If
  a framework, step, script line or number isn't in a source you've read, it
  doesn't go in.
- When a source can't be opened, log it as **unread** and tell the user. Never
  fill the gap from general knowledge.
- Numbers in the references are examples from Frankie's own material. Never
  present them as expected results for a new client.

## Workflow: applying the frameworks

1. Read `references/frameworks.md`, then the topic file(s) the task needs.
2. Name the framework(s) you're applying and cite their source tags in your
   output, e.g. "IVQ pricing [Z8, Z12]".
3. Write in Frankie's voice (`voice.md`), with no profanity.
4. If the task needs something the frameworks don't cover, say so and ask the
   user rather than improvising in Frankie's name.

## Workflow: adding a new source

1. Add a row to `references/source-index.md` with the next ID (Z31…), title,
   type and location.
2. Read the full source. For video, use the transcript, and ask the user for one
   if none exists.
3. Add the points to the right topic file with the source tag. Keep Frankie's
   wording for scripts and named steps; paraphrase explanations.
4. Mark contradictions between sources instead of resolving them silently, and
   attribute guest or mentor material (e.g. Travis Sago) correctly.
